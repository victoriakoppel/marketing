# Kino Pulse

Дашборд ежедневной аналитики кинопроката: текущий срез афиши и накопительная
динамика по дням. Статический сайт без сборки и без бэкенда — три файла
фронтенда плюс Python-сборщик, который раз в сутки складывает снимок в JSON.

## Быстрый старт

```bash
cd kino-pulse
python3 -m http.server 8000        # открыть http://localhost:8000
```

Из коробки показываются демо-данные за 14 дней: цифры синтетические, интерфейс
честно предупреждает об этом баннером. Пересоздать их:

```bash
pip install -r collector/requirements.txt
python collector/make_demo.py --days 14
```

## Как это работает

```
источник (сайт афиши)
        │  collector/collect.py — раз в сутки, 06:00 Алматы
        ▼
data/snapshots/YYYY-MM-DD.json     полный снимок дня, архив, не переписывается
        │  collect.py --rebuild
        ▼
data/latest.json  +  data/history.json
        │  fetch() при загрузке страницы
        ▼
index.html + app.js + styles.css
```

Снимки — источник истины. `latest.json` и `history.json` из них пересобираются,
поэтому их можно удалить и восстановить в любой момент: `--rebuild`.

## Сбор данных

Разбор страницы идёт от надёжного к хрупкому — первый сработавший способ выигрывает:

1. **JSON-LD** (`schema.org`: `ScreeningEvent`, `Movie`). Размечен самим сайтом,
   переживает редизайн. `ScreeningEvent` — это один сеанс: их количество и есть
   «сеансы сегодня», минимум по `offers.price` — «цена от», `aggregateRating`
   у `Movie` — оценка и число отзывов.
2. **Состояние SPA** (`__NEXT_DATA__`, `__NUXT__`, `__INITIAL_STATE__`). Данные
   структурированы, но ключи у каждого сайта свои — маппинг пишется под сайт.
3. **CSS-селекторы** из `SOURCES` в `collect.py`. Последний рубеж, ломается при
   любой переверстке.

Прежде чем настраивать сбор, посмотрите, что источник вообще отдаёт:

```bash
python collector/collect.py --probe --source ticketon --city almaty
```

`--probe` печатает размер страницы, найденные типы JSON-LD, наличие состояния
SPA, число совпадений CSS-селектора и первые разобранные фильмы. По этому выводу
правится блок `SOURCES[...]["css"]` — все селекторы собраны в одном месте.

Боевой запуск:

```bash
python collector/collect.py --source ticketon --city almaty
```

## Про «билеты продано» — важное

Продажи билетов **не публикуются как открытые данные** ни одним кинотеатром или
агрегатором. Всё остальное на дашборде открыто и берётся напрямую: афиша,
оценки, число отзывов, цены, расписание сеансов. Продажи — нет.

Поэтому `total_sales` заполняется только тогда, когда источник отдаёт занятость
зала (`maximumAttendeeCapacity` и `remainingAttendeeCapacity` у сеанса), и тогда
это число занятых мест, помеченное `"sales_basis": "seats_taken"` — оценка
снизу по одной площадке, а не касса фильма.

Если источник таких полей не даёт, `total_sales` остаётся `null`, и дашборд
честно деградирует: KPI показывает прочерк с подписью «источник не публикует
продажи», графики и рейтинги переключаются на сеансы и отзывы, сортировка «по
продажам» отключается. Ни одного выдуманного числа в интерфейс не попадает.

```jsonc

  "collected_at": "2026-08-31T06:00:00+06:00",
  "city": "almaty",
  "source": "Ticketon",
  "strategy": "json-ld",        // как разобрали: json-ld | css | demo
  "is_demo": false,             // true → баннер-предупреждение в интерфейсе
```

## Автоматизация

`.github/workflows/kino-pulse.yml` запускает сбор в 00:00 UTC (06:00 Алматы),
коммитит новый снимок и пересобранные `latest.json` / `history.json`. Запуск
руками — через **Actions → Run workflow** с выбором источника и города.

Публикация: включите GitHub Pages на ветке и папке `kino-pulse/` — сайту не
нужен ни бэкенд, ни сборка.

## Что стоит знать перед боевым запуском

- **Селекторы в `SOURCES` не проверены на живых сайтах.** Они написаны вслепую:
  в окружении, где собирался проект, исходящий доступ в интернет закрыт
  политикой сети, поэтому ни одну страницу источника открыть не удалось.
  Путь через JSON-LD не зависит от вёрстки и должен работать сразу; путь через
  CSS почти наверняка потребует правки после `--probe`.
- **Уважайте источник.** Проверьте `robots.txt` и условия использования сайта,
  не наращивайте частоту: одного запроса в сутки хватает, весь смысл проекта —
  в ежедневной точке, а не в реальном времени.
- **История накапливается только вперёд.** Задним числом данные взять неоткуда,
  поэтому графики динамики оживают со второго сбора — до этого показывается
  явная заглушка, а не пустой прямоугольник.
